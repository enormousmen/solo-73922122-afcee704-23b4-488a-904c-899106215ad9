# 植被调查离线修订合并平台

数据员把外业队的离线修订 CSV 并回当前记录库，供物种分布分析入库。
FastAPI + SQLite 实现，三方向（基线 / 修订 / 当前）逐字段合并，冲突人工裁决，整批事务化应用；
并支持「同一样方、同一物种仅一条汇总记录」的唯一性口径，可在网页上检查并启用。

## 快速启动（Docker Compose）

```bash
docker compose up --build
```

启动后有**两个共库 Web 进程**（同一 SQLite 数据库、同一数据卷）：

- 进程 A：**http://localhost:8000**
- 进程 B：**http://localhost:8001**

页面右上角显示当前进程标识。两个进程可并发做启用、维护与合并确认，
约束对双方同等生效，任一方都无法绕过。SQLite 数据持久化在名为 `survey-data` 的卷中；
首次启动自动载入 `data/initial_records.csv` 的 12 条初始记录。

本地开发（可选）：

```bash
pip install -r requirements.txt
uvicorn app.main:app   # http://localhost:8000
```

## 数据格式

记录 = 唯一 ID + 样方 + 物种 + 非负整数株数。CSV 固定表头：

```csv
id,quadrat,species,count
R001,Q1,羊草,12
```

## 唯一性口径（新）

**同一样方、同一物种仅保留一条汇总记录**，避免重复株数进入分析。

- 样方、物种分别**去除首尾空白后精确匹配**；株数不参与匹配，**株数不同也算重复**。
- 重复检查列出每个重复组及其全部记录 ID（及各自株数）。

### 检查与启用页（`/uniqueness`）

1. **启用前全库检查为只读快照，不持 SQLite 写锁**：检查期间其他页面的人工维护、
   离线合并照常进行。
2. 点「启用」时，在一个立即写事务内**以切换瞬间的完整数据复检**：
   - 有重复 → 回滚、**不启用**，页面列出重复组与记录 ID；启用状态与数据均不改变，
     失败或中断不会留下“半启用”状态；
   - 无重复 → 同事务写入启用标志，提交后生效。
3. 启用标志保存在数据库 `settings` 表中，**服务重启后依然生效**；重复点击启用是幂等的。

### 启用后的约束

| 场景 | 行为 |
|---|---|
| 人工新增 / 单条修改 / 删除 | 提交时按最终状态检查；重复则整批拒绝并显示相关记录 ID，记录不变 |
| 整批修改（首页「整批保存全部修改」） | 单事务提交，按**整批最终状态**检查；允许同批交换两条记录的物种（中间重复、最终不重复可通过） |
| 离线合并确认（含启用前生成的旧预览） | 整批动作在同一事务应用后复检；重复则整批回滚，预览保持「待确认」，**不会标为已应用** |
| 两个共库 Web 进程并发 | 进程内锁 + SQLite `BEGIN IMMEDIATE` 立即写事务串行化，全库同一时刻只有一个写事务 |

### 并发正确性的实现要点

- 每个写事务以 `BEGIN IMMEDIATE` 立即取得全库写锁，配合 `busy_timeout` 排队；
- 唯一性检查在写事务内、提交前对**整批最终状态**进行，因此多条语句组成的批次
  （如交换两条记录的物种）可以成功，而最终状态重复的批次整体回滚；
- 启用状态每次请求都从数据库读取，不做进程内缓存，一个进程启用后另一个进程立即受约束。

## 使用流程（网页四步）

1. **当前记录**：首页表格直接改值/删除/新增，也可整批保存；`导出当前 CSV` 可随时下载。
2. **保存基线并导出**：点按钮把当前记录整体存为基线，并下载对应 CSV 交给外业队离线修订。
3. **上传修订**：选择该修订所基于的基线，上传外业队改完的 CSV。
   - 修订文件中**缺行 = 删除**该记录；**新 ID = 新增**。
   - 系统逐字段比较基线、修订、当前三方，生成合并预览。
4. **预览与确认**：
   - 不同字段各改各的 → 自动合并；双方改成相同值 → 只留一份；
   - 双方同字段改不同值、同 ID 新增内容不同、删除与修改相遇 → 展示三方值，逐项人工选择；
   - 全部裁决后一键**整批确认**，只应用离线改动。

## 合并规则（三方）

| 情形 | 结果 |
|---|---|
| 仅修订改了某字段 | 自动采用修订值 |
| 仅当前改了某字段 | 自动保留当前值 |
| 双方改成相同值 | 自动保留一份 |
| 双方同字段改不同值 | 冲突，人工选修订值或当前值 |
| 修订缺行（删除）且当前未改 | 自动删除 |
| 修订删除 vs 当前已修改 | 冲突：删除 或 保留当前 |
| 修订修改 vs 当前已删除 | 冲突：按修订恢复 或 保持删除 |
| 双方各自新增同 ID 同内容 | 只留一份 |
| 双方各自新增同 ID 不同内容 | 冲突：二选一 |

## 过期保护与事务性

- 预览生成时对**计划触及的记录**拍快照；确认时重新核对。
  拟改记录在预览后又被修改或删除 → **拒绝旧预览**，按最新当前记录自动重新比较；
  **无关记录的变化不影响确认**。
- 整批应用在单个事务中执行，任何失败（含唯一性重复拒绝）整体回滚，**当前数据不变**。

## 唯一性功能演示（浏览器可复现）

初始 12 条记录本身无重复，可直接启用。建议用两个端口（8000 / 8001）交叉操作验证并发。

### 演示 1：检查 → 发现重复 → 拒绝启用 → 整理 → 启用

```text
1. 首页新增记录：ID=R301，样方= Q1 （前后带空格），物种= 羊草 ，株数=4
   → 与 R001（Q1/羊草）按去空白精确匹配构成重复（株数不同也算）
2. 打开 /uniqueness：只读检查列出重复组「Q1 + 羊草」，记录 ID：R001、R301；
   启用按钮禁用
3. 直接 POST 启用（若用工具）也会被拒绝：仍为未启用，数据不变
4. 回首页删除 R301，再回 /uniqueness 点启用 → 启用成功，重启后仍为已启用
```

### 演示 2：启用后人工维护的整批拒绝与同批交换

```text
1. 启用后，新增 R302=Q1/羊草 → 整批拒绝，提示含相关 ID（R001、R302），R302 不入表
2. 首页同时把 R001 物种改为「针茅」、R002 物种改为「羊草」，点「整批保存全部修改」
   → 同批交换两条记录的物种，最终无重复，成功
3. 再把 R001 改为 Q1/冷蒿（撞 R003）后整批保存 → 整批拒绝、列出 ID，两条记录均不变
```

### 演示 3：离线合并的重复拒绝（旧预览同样受约束）

```text
1. 首页「保存当前记录为基线」得到基线 #1（启用前保存的基线也可以）
2. 上传 samples/uniqueness_duplicate_reject.csv（选基线 #1）
   → 预览显示新增 R301=Q1/羊草，与 R001 重复；预览保持「待确认」
3. 点确认 → 整批拒绝，页面列出相关记录 ID，R301 未写入，预览不会标为「已应用」
4. 改传 samples/uniqueness_swap_species.csv（R001 与 R002 交换物种）
   → 确认成功：整批最终状态无重复，预览标为「已应用」
```

### 演示 4：两个共库进程并发

```text
1. 浏览器分别打开 http://localhost:8000 与 http://localhost:8001
2. 在 8000 启用唯一性后，刷新 8001 的 /uniqueness → 同样显示已启用
3. 两个页面同时提交与现有键重复的新增 → 两边都被整批拒绝，库里无残留
4. 一边整批交换物种、另一边同时提交撞键修改 → 交换成功、撞键整批拒绝，最终全库无重复
```

## 交叉修订演示样例（原有三方合并）

`samples/` 下另有两队基于初始数据的离线修订，可直接在网页上传演示：

```text
1. 首页点「保存当前记录为基线并导出 CSV」→ 得到基线 #1
2. 在当前记录里把 R003 株数改为 7、R009 株数改为 8（模拟库内同期改动）
3. 上传 samples/team_a_revision.csv（选基线 #1）
   → 9 项自动合并（改 R002/R003/R004/R005/R009/R010、删 R008、增 R101/R102），无冲突，直接确认
4. 上传 samples/team_b_revision.csv（仍选基线 #1）
   → 自动合并：R005 物种改扁穗冰草（与 A 的株数改动字段级合并）、R007 株数、新增 R201
   → 冲突：R002 双方改不同株数；R003 队B删除 vs 当前已改；R102 双方新增内容不同
5. 先别确认：回首页把 R007 株数改为 20，再回预览点确认
   → 旧预览被拒绝并自动重新比较（R007 变成新冲突）；R009 等无关改动不阻碍确认
6. 裁决全部冲突后确认 → 整批应用
```

## 项目结构

```text
app/
  main.py        FastAPI 路由：记录维护、整批修改、唯一性检查/启用、基线、上传、预览、确认
  merge.py       三方向逐字段合并与冲突裁决合成
  csvio.py       修订 CSV 解析（校验非负整数株数等）与导出
  uniqueness.py  唯一性口径（去空白精确匹配、重复组、DuplicateError）
  db.py          SQLite 访问层；立即写事务 + 提交前整批唯一性检查；启用状态持久化
  templates/     页面模板（含 uniqueness.html 检查与启用页）
data/initial_records.csv             初始数据（首次启动自动载入）
samples/team_a_revision.csv          队 A 交叉修订样例
samples/team_b_revision.csv          队 B 交叉修订样例
samples/uniqueness_swap_species.csv  唯一性演示：同批交换两条记录的物种（应通过）
samples/uniqueness_duplicate_reject.csv  唯一性演示：整批产生重复（应拒绝）
Dockerfile / docker-compose.yml      双共库 Web 进程（8000 / 8001）
```
